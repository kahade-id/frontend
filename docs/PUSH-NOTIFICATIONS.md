## Dua channel Android, bukan satu

```
transaksi   MAX      Status order, dana escrow, batas waktu bayar
default     DEFAULT  Pengumuman dan sisanya
```

Kalau hanya ada satu channel, pengguna yang terganggu pengumuman hanya punya
satu pilihan: mematikan semua notifikasi — termasuk "dana sudah masuk". Dua
channel membuat keduanya bisa dipisah dari Setelan Android.

Nilai `default` **wajib** sama dengan `defaultChannel` di plugin
`expo-notifications`; itulah channel yang dipakai FCM saat payload tidak
menyertakan `channelId`. Kalau tidak cocok, notifikasi menunjuk channel yang
tidak pernah dibuat dan **hilang tanpa error**. Dijaga `npm run check:push`.

**Agar backend memakai channel `transaksi`,** payload harus menyebutkannya:

```jsonc
// Expo Push API
{ "to": "ExponentPushToken[…]", "channelId": "transaksi", "title": "…", "body": "…" }
```

### Channel bersifat sekali tulis

Setelah channel dibuat di sebuah perangkat, `importance`, suara, dan getar
menjadi milik **pengguna**. Memanggil `setNotificationChannelAsync` lagi dengan
nilai berbeda tidak mengubahnya (hanya `name`/`description` yang ikut). Kalau
suatu saat perlu perilaku berbeda, buat ID channel baru (mis. `transaksi-v2`)
— mengubah angka di kode saja tidak akan berpengaruh bagi pengguna lama.

### Suara

Kedua channel memakai `sound: "default"` (nada notifikasi sistem). Tidak ada
berkas suara kustom, jadi `sounds: []` di plugin sengaja kosong.

Notifikasi yang tiba saat **aplikasi sedang dibuka** tetap senyap
(`shouldPlaySound: false` di handler foreground). Itu keputusan lama yang
dipertahankan: pengguna sedang melihat layar, dan Banner in-app yang memberi
konteks.

## `aps-environment` = `development`, dan itu memang benar

```json
"ios": { "entitlements": { "aps-environment": "development" } }
```

Terlihat salah untuk produksi, tetapi tidak. Dokumentasi Expo menyatakan:
*"The iOS APNs entitlement is always set to 'development'. Xcode automatically
changes this to 'production' in the archive generated by a release build."*
([expo-notifications](https://docs.expo.dev/versions/latest/sdk/notifications/))

Menuliskan `production` secara manual justru merusak build development dan
simulator: token yang diterbitkan adalah sandbox, sedangkan entitlement
menunjuk endpoint produksi. `check-push` memberi CATATAN (bukan error) kalau
menemukan `production`, karena ada kasus langka ITMS-90078 yang butuh itu.

Plugin `expo-notifications` hanya mengisi nilai ini **bila belum ada**
(`if (!config.modResults['aps-environment'])`), jadi nilai di `app.json`
selalu menang. Terverifikasi pada `ios/Kahade/Kahade.entitlements` hasil
prebuild.

## Kenapa placeholder FCM dijaga skrip, bukan komentar

`google-services.json` placeholder memakai `package_name: id.kahade` supaya
plugin Gradle `com.google.gms.google-services` tidak menolaknya. Efek
sampingnya berbahaya: **build tetap sukses** dengan kredensial palsu.
Aplikasinya terpasang, terlihat normal, dan push Android diam-diam tidak
pernah sampai — baru ketahuan dari keluhan pengguna setelah rilis.

Karena itu `scripts/check-push.mjs` menghentikan build. Skrip ini terdaftar
sebagai npm script `eas-build-pre-install`, yang dijalankan EAS Build secara
otomatis, jadi tidak ada jalan pintas "lupa menjalankan preflight". Skrip
hanya memakai modul bawaan Node karena hook itu berjalan sebelum
`npm install`.

Yang diperiksa:

1. `google-services.json` ada, JSON valid, **bukan placeholder**
2. `package_name` di dalamnya cocok dengan `android.package`
3. `aps-environment` ada dan valid
4. plugin `expo-notifications` punya `icon` (berkasnya ada) dan `defaultChannel`
5. `POST_NOTIFICATIONS` ada di `android.permissions`
6. `defaultChannel` benar-benar ada di `NOTIFICATION_CHANNELS`

Lolos sementara untuk build yang tidak butuh push:

```bash
KAHADE_ALLOW_PLACEHOLDER_FCM=1 npx eas build --profile preview --platform android
```

## Yang masih Anda perlukan sebelum build production

### 1. `google-services.json` asli — SELESAI

Berkas konfigurasi aplikasi Firebase sudah ada di root repo. Preflight telah
memastikan JSON valid, bukan placeholder, dan memiliki Android client dengan
package name **`id.kahade`** yang sama dengan `app.json`.

Berkas ini adalah konfigurasi client yang ikut dikemas dalam APK, bukan service
account dengan private key. Jika Firebase menerbitkan konfigurasi baru, timpa
berkas yang sama lalu jalankan kembali `npm run check:push`.

### 2. FCM V1 service account key — WAJIB, diunggah ke EAS bukan ke repo

Firebase Console → Project settings → **Service accounts** → Generate new
private key (JSON).

```bash
eas credentials --platform android
# → pilih profil → Google Service Account → Manage FCM V1 service account key
```

Berkas ini **rahasia** (kunci privat, akses penuh ke project Firebase).
Jangan pernah masuk repo. Tanpa ini, EAS/Expo Push API tidak bisa mengirim ke
Android walau `google-services.json` sudah benar.

### 3. APNs key iOS — WAJIB untuk push iOS

Apple Developer → Certificates, Identifiers & Profiles → Keys → buat key
dengan **Apple Push Notifications service (APNs)** dicentang, unduh `.p8`
(hanya bisa diunduh sekali).

```bash
eas credentials --platform ios
# → Push Notifications: Manage your Apple Push Notifications Key
```

Atau biarkan `eas build --platform ios` membuatkannya otomatis kalau akun
Apple Developer sudah tertaut. Satu APNs key berlaku untuk sandbox dan
produksi sekaligus.

### 4. Yang TIDAK Anda perlukan

- `GoogleService-Info.plist.xml` yang tersimpan di root valid untuk bundle
  `id.kahade`, tetapi sengaja tidak direferensikan oleh `app.json`. Kahade
  memakai APNs langsung lewat Expo dan tidak memasang Firebase SDK di iOS;
  berkas tersebut tidak menggantikan APNs key `.p8`.
- Sertifikat APNs `.p12` gaya lama — `.p8` menggantikannya.

## Perlu dicek di perangkat: warna ikon notifikasi

`notification_icon_color` bernilai `#000000` (terikat ke
`tokens.colors.light.primary` oleh `check:tokens` #8). Android memakai warna
ini untuk mewarnai ikon kecil dan nama aplikasi di notification shade.

Di shade bertema **terang** hasilnya bagus. Di shade **gelap** (dark mode),
hitam berpotensi nyaris tak terlihat. Perilakunya berbeda antar OEM dan saya
tidak menemukan sumber yang meyakinkan untuk semua kasus, jadi ini perlu
**diuji langsung** pada satu perangkat Android dalam dark mode sebelum rilis.

Kalau ternyata bermasalah, ada dua pilihan, keduanya menyentuh `check:tokens`
#8 karena warna itu sedang dikunci ke token:

1. pakai abu-abu netral yang cukup kontras di kedua tema, atau
2. hapus `color` sepenuhnya sehingga Android memakai aksen sistem yang
   mengikuti tema.

Ikon itu sendiri sudah benar: 96×96 (xxxhdpi), siluet putih dengan 53,6% area
transparan, sehingga Android bisa membentuk siluetnya. Prebuild menurunkannya
ke 24/36/48/72/96 px.
