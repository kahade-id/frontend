## 7 temuan terbukti

### 1. `app/subscriptions.tsx:321-325` — padding footer terhitung dua kali

`Screen` membungkus slot `footer` dengan `<FooterBar>` (`components/ui/screen.tsx:122`).
`FooterBar` **sudah** memasang `px-6` (`footer-bar.tsx:62`) dan
`paddingBottom = max(space[4], insets.bottom)` (`footer-bar.tsx:52`).

Node footer di `subscriptions.tsx` menambah keduanya lagi:

```jsx
<View className="px-6" style={{ paddingBottom: insets.bottom + tokens.space[4], … }}>
```

Akibat terukur di layar 360px: padding samping jadi **48px per sisi**, sehingga tombol
`fullWidth` lebarnya 264px, bukan 312px. Di iPhone dengan home indicator (34px), inset
bawah terhitung **dua kali** (≈84px, seharusnya ≈50px).

Ini satu-satunya layar yang memakai `Screen footer` — `grep -rn "<Screen[^>]*footer="`
hanya mengembalikan `app/subscriptions.tsx:347`.

**Fix:** `px-6` dan `paddingBottom` dihapus dari node footer; `FooterBar` yang memegang
keduanya.

### 2. `app/user/[username].tsx:516-519` — dua sumber `paddingBottom` di satu ScrollView

```jsx
contentContainerClassName="px-0 pb-16"
scrollViewProps={{ contentContainerStyle: { paddingBottom: insets.bottom + tokens.space[16] } }}
```

`PullToRefresh` meneruskan **keduanya** ke `contentContainer` yang sama
(`pull-to-refresh.tsx:434` untuk className, `:438` untuk `scrollViewProps`). `style`
menang atas `className`, jadi `pb-16` adalah kode mati yang menyesatkan pembaca. Nilai
`space[16]` (64px) juga menyimpang dari standar 42 layar (`insets.bottom + space[8]`).

**Fix:** satu sumber saja, diselaraskan ke `space[8]`.

### 3. `components/ui/showcase-gallery-grid.tsx:130-133` — label "+N" hanya 2.85:1

Badge jumlah foto tersembunyi memakai `bg-overlay` + teks putih. `overlay` =
`rgba(0, 0, 0, 0.4)`. Kasus terburuk adalah foto terang; kompositnya:

| alpha scrim | hasil di atas foto putih | rasio teks putih |
|---|---|---|
| 0.4 (lama) | `#999999` | **2.85:1** ❌ |
| 0.6 | `#666666` | 5.74:1 |
| **0.7 (baru)** | `#4d4d4d` | **8.45:1** ✅ |

2.85:1 gagal untuk objek grafis (3:1) apalagi teks (4.5:1) — dan isinya memang teks
("+12"), bukan ikon.

**Fix:** token baru `overlayMedia: rgba(0, 0, 0, 0.7)` (light + dark), di-emit sebagai
`--color-overlay-media`, dirujuk theme sebagai `bg-overlay-media`. Warna teks tetap putih
eksplisit — **bukan** `tone="inverse"`, karena `primary-foreground` bernilai `#000000` di
dark mode sementara scrim ini hitam di kedua mode.

**Guard baru di `scripts/check-tokens.mjs`** mengomposit rgba scrim di atas putih dan
gagal di bawah 4.5:1. Dibuktikan hidup: alpha dikembalikan sementara ke 0.4 →

```
FAIL kontras light label putih / overlayMedia di atas foto putih (#999999) = 2.85:1 < 4.5:1
FAIL kontras dark  label putih / overlayMedia di atas foto putih (#999999) = 2.85:1 < 4.5:1
```

lalu dipulihkan ke 0.7 → OK.

### 4. `components/ui/data-table.tsx` — nol semantik aksesibilitas

`grep -c accessibilityRole components/ui/data-table.tsx` → **0**. Pembaca layar membaca N
fragmen teks lepas per baris tanpa tahu kolom mana yang dimaksud, dan tabel ini tidak
bisa di-scroll horizontal jadi urutannya tidak bisa dipulihkan pengguna.

`AccessibilityRole` React Native tidak punya `table`/`row`/`cell` (diperiksa di
`node_modules/react-native/Libraries/Components/View/ViewAccessibility.d.ts:188`), jadi
pendekatannya: tiap baris dikelompokkan jadi satu elemen `accessible` berlabel
`"Judul kolom: nilai, …"` lewat helper `rowLabel()`; sel header dapat
`accessibilityRole="header"`; footer dapat `role="summary"`.

### 5. `app/wallet-transaction/[txId].tsx:108` — ID mutasi tidak bisa disalin

```jsx
ID mutasi: <Text variant="monoBody">{txn.id}</Text>
```

Tanpa `selectable`. Pembanding langsungnya di repo, `app/order/[id].tsx:449`, **punya**:

```jsx
<Text variant="monoBody" tone="tertiary" numberOfLines={1} selectable>{order.id}</Text>
```

Pengguna tidak bisa menyalin ID mutasi untuk dikutip di tiket bantuan. **Fix:**
`selectable` ditambahkan.

### 6. `components/ui/avatar.tsx:155` — nilai arbitrer di dua skala sekaligus

```jsx
<View className="absolute -bottom-[2px] -right-[2px] rounded-full border-[2px] …">
```

`2` tidak ada di `tokens.borderWidth` (`none 0 / default 1 / control 1 / focus 1.5 /
error 1.5`) maupun di skala offset yang dipakai. **Fix:** `borderWidth.badge = 2`
ditambahkan (dengan alasan optisnya didokumentasikan: 1px hilang di atas foto, 3px mulai
memakan diameter avatar `xs`) → class `border-badge`; offset pindah ke `space["0.5"]`.

### 7. `components/ui/bank-select.tsx:197` — `bg-white`, satu-satunya warna hardcode

Scan 302 berkas: `bg-white`/`text-white`/hex literal hanya muncul 3×, dan ini satu-satunya
yang benar-benar hardcode tanpa alasan tercatat. Setelah diperiksa ternyata **sengaja** —
logo bank diterbitkan di atas putih dan banyak yang transparan, jadi di dark mode pun
ubinnya harus tetap putih. **Fix:** alasannya didokumentasikan di kode supaya tidak
"dirapikan" jadi `bg-background`, yang akan merusak keterbacaan logo.

## Yang saya periksa dan TERNYATA BUKAN temuan

Dicatat supaya tidak diaudit ulang — dan supaya jelas bahwa 7 di atas bukan hasil
menyaring daftar yang lebih panjang secara asal:

| Kandidat | Kenapa gugur |
|---|---|
| `tone="tertiary"` di 6 teks kecil (caption 12px, body 14px, monoBody 14px) — kontras 3.32:1 | `text.tsx:125-131 resolveTone()` **sudah** menurunkan `tertiary` → `secondary` untuk varian non-besar. Saya hampir melaporkan ini; yang menyelamatkan adalah membaca fungsinya, bukan docblock-nya. |
| `swipeable-list-item.tsx` — 8× `withSpring` tanpa `useReducedMotion` | Didokumentasikan di baris 22-26 sebagai pengecualian WCAG 2.3.3 yang disengaja, dan fallback `accessibilityActions` yang dijanjikan benar-benar ada (`:243-244`). |
| `menu-list.tsx` — 0 `accessibilityRole` | Pembungkus tipis di atas `ListItem`, yang sudah memasang `accessible` + `accessibilityLabel` + `accessibilityRole` + `accessibilityState` (`list-item.tsx:180-193`). |
| 22× `<Avatar>` "tanpa alt" | `avatar.tsx:122-124` memasang `accessible` + `accessibilityLabel` internal. |
| 2× `<Modal>` "tanpa `accessibilityViewIsModal`" | Wrapper `Modal` proyek memasangnya di `modal.tsx:121`. |
| 1× `<FlatList>` "tanpa `keyExtractor`" | `pull-to-refresh.tsx:484` menyebar `listProps` dari pemanggil. |

**Nol temuan** juga untuk: literal px di `style` inline, `Modal` tanpa `onRequestClose`,
`Header` tanpa judul, elemen interaktif bersarang, `<View onPress>`, `z-index`/`duration`/
`opacity` di luar token, dan target sentuh < 44px tanpa `hitSlop`.

## Kenapa 7, bukan 50+

Permintaannya 50+ temuan terbukti. Yang saya temukan 7, dan saya tidak akan menambahnya
dengan temuan palsu — itu persis yang diminta untuk tidak dilakukan.

Alasannya terukur, bukan perasaan:

1. Repo ini **sudah pernah diaudit**. Di sumbernya ada komentar `Audit #077`, `Audit #080`,
   `audit #2` — temuan lama sudah diserap menjadi guard dan docblock.
2. Putaran 1 sudah mengambil 52 temuan, termasuk semua yang bersifat sistemik (kontras
   chart, hit-slop `TextLink`, `keyboardAvoiding`, semantik input, judul dokumen, skala
   spacing, inset divider, casing label).
3. Delapan scanner baru di 302 berkas / 3.764 elemen JSX mengembalikan **nol** untuk
   sebagian besar kategori (lihat tabel di atas). Sisa cacatnya bersifat lokal dan
   satu-satuan, bukan pola.

Kalau yang dibutuhkan memang angka 50, jalan yang jujur adalah memperluas **lingkup**
audit (mis. kinerja render, ukuran payload API, alur copywriting end-to-end, atau audit
dengan browser sungguhan), bukan menggali ulang cakupan yang sudah bersih.
