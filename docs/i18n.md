# i18n — Bahasa Indonesia & English

Ditulis karena satu laporan produk: "aktifkan ubah bahasa Inggris, sekarang cuma
Bahasa Indonesia yang tersedia". Opsi English memang sudah ada di
`GET/PUT /v1/settings/language`, tapi tidak pernah mengubah apa pun — UI-nya
hardcode Indonesia dan baris "Bahasa" di Pengaturan menulis `Indonesia` sebagai
status. Dokumen ini menjelaskan desain yang menggantikannya dan cara merawatnya.

## Model: teks sumber = kunci kamus

String Indonesia di kode adalah kuncinya; kamus hanya berisi
`"<teks Indonesia>": "<English>"`.

| Bukan begitu | Kenapa |
| --- | --- |
| `t("settings.language.title")` | Butuh registri kunci; string yang belum didaftar menampilkan `settings.language.title` ke user atau `undefined`. Dengan kunci-teks, yang tampil adalah teks Indonesia yang memang benar — fallback yang aman. |
| Terjemahan dievaluasi sekali di module scope | Nilai `DEFAULT_LANGUAGES` yang sudah "diterjemahkan" saat import tidak akan pernah berubah saat user berpindah bahasa. Terjemahan terjadi di titik render. |

## Titik render

`components/ui/text.tsx` adalah satu-satunya komponen yang memanggil `RNText`
(repo ini memang melarang `<Text>` RN langsung). Di sanalah terjemahan dipasang:

- `useLanguage()` → setiap simpul teks berlangganan store bahasa, jadi seluruh
  app berpindah bahasa **tanpa me-remount Stack** (remount = user terlempar ke
  Beranda setiap ganti bahasa).
- `localizeChildren(children)` → hanya string murni yang diterjemahkan; angka,
  elemen, dan `{ekspresi}` lewat utuh.

Yang TIDAK lewat `<Text>` dan therefore ditambal sendiri di primitifnya:
`placeholder` (RN TextInput), `accessibilityLabel`/`accessibilityHint` di field
(`input.tsx`, `phone-input.tsx`, `tag-input.tsx`, `chat-composer.tsx`), dan
`document.title` (`header.tsx`).

## Bentuk string dinamis (`{x}`)

`Saldo Rp1.250.000 keluar` tidak akan pernah sama persis dengan kunci kamus apa
pun. Karena itu `lib/i18n/shape.ts` memaski angka menjadi token `{x}` dan
mencari kamus dalam BENTUK itu, lalu menyisipkan kembali nilainya:

```
kunci   : "Saldo {x} keluar"
English : "Balance {x} out"
input   : "Saldo Rp1.250.000 keluar"  →  output: "Balance Rp1.250.000 out"
```

Yang tidak numeric dan tidak bisa dideteksi dari string jadi (nama orang, slug)
harus ditulis eksplisit di layarnya: `t("Kirim ke {name}", { name })`.

## Urutan bahasa aktif

1. **Preferensi akun** — `GET /v1/settings/language`, ditarik sekali per sesi
   oleh `components/i18n-provider.tsx` dan menang atas semuanya.
2. **Cache perangkat** — `SecureKeys.languagePreference` (expo-secure-store;
   ikut localStorage di web seperti preferensi tema), dipakai sebelum & saat
   offline.
3. **Bahasa OS** — `expo-localization`: `id` hanya bila OS memang Indonesia,
   selain itu `en` (English satu-satunya kamus yang ada).

Ganti bahasa di `/language`: optimistis → store + cache → `PUT`; bila PUT gagal,
bahasa dikembalikan dan toast menampilkan alasan dari server.

## Merawat katalog

```
npm run gen:i18n     # tulis ulang lib/i18n/catalog.json dari sumber
npm run check:i18n   # CI: katalog sinkron + kamus valid + cakupan tidak turun
```

`check:i18n` (→ `scripts/check-i18n.mjs`) menolak:

- kunci di kamus yang tidak ada di katalog (copy Indonesia berubah di kode);
- jumlah token `{x}` berbeda antara kunci & nilai;
- kunci ganda antar file kamus;
- cakupan yang turun dari `lib/i18n/coverage.json` (ratchet).

Kamus dipecah per area (`lib/i18n/en/{labels,auth,tabs,ui,screens-*}.json`)
supaya satu layar bisa diterjemahkan tuntas dalam satu review; daftar kerja per
area: `npm run gen:i18n -- --areas`.

## Known gap (disengaja, tercatat)

- Label aksesibilitas pada komponen kustom yang tidak merender `<Text>`
  (beberapa `accessibilityLabel` di kartu/list) baru mengikuti bahasa pada
  render berikutnya. Visible text selalu benar.
- Teks hasil perantaian di layar (`"Rp" + x`) ikut terbaca lewat bentuk `{x}`;
  kalau bentuknya tabrakan, penulis layar menuliskan `t(...)` eksplisit.
- Dokumen hukum & artikel bantuan isinya datang dari backend — tidak ikut
  kamus client.
