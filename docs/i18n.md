# i18n — Bahasa Indonesia & English

Ditulis karena satu laporan produk: "aktifkan ubah bahasa Inggris, sekarang cuma
Bahasa Indonesia yang tersedia". Opsi English memang sudah ada di
`GET/PUT /v1/settings/language`, tapi tidak pernah mengubah apa pun — UI-nya
hardcode Indonesia dan baris "Bahasa" di Pengaturan menulis `Indonesia` sebagai
status. Dokumen ini menjelaskan desain yang menggantikannya dan cara merawatnya.

## Model: teks sumber = kunci kamus

String Indonesia di kode adalah kuncinya; kamus hanya berisi
`"<teks Indonesia>": "<English>"`.

| Bukan begitu | Kenapa |
| --- | --- |
| `t("settings.language.title")` | Butuh registri kunci; string yang belum didaftar menampilkan `settings.language.title` ke user atau `undefined`. Dengan kunci-teks, yang tampil adalah teks Indonesia yang memang benar — fallback yang aman. |
| Terjemahan dievaluasi sekali di module scope | Nilai `DEFAULT_LANGUAGES` yang sudah "diterjemahkan" saat import tidak akan pernah berubah saat user berpindah bahasa. Terjemahan terjadi di titik render. |

## Titik render

`components/ui/text.tsx` adalah satu-satunya komponen yang memanggil `RNText`
(repo ini memang melarang `<Text>` RN langsung). Di sanalah terjemahan dipasang:

- `useLanguage()` → setiap simpul teks berlangganan store bahasa, jadi seluruh
  app berpindah bahasa **tanpa me-remount Stack** (remount = user terlempar ke
  Beranda setiap ganti bahasa).
- `localizeChildren(children)` → hanya string murni yang diterjemahkan; angka,
  elemen, dan `{ekspresi}` lewat utuh.

Yang TIDAK lewat `<Text>` dan therefore ditambal sendiri di primitifnya:
`placeholder` (RN TextInput), `accessibilityLabel`/`accessibilityHint` di field
(`input.tsx`, `phone-input.tsx`, `tag-input.tsx`, `chat-composer.tsx`), dan
`document.title` (`header.tsx`).

## String yang dirakit dinamis (props, label aksesibilitas)

`localizeChildren` hanya melihat **children** `<Text>`. Semua teks yang dikirim
lewat PROP (termasuk `accessibilityLabel`/`accessibilityHint`, `title`,
`description`, `placeholder`, `helperText`, `processingMessage`, …) tidak
pernah dilihatnya, jadi harus lewat `translate()` sendiri. Tiga aturan yang
dijaga `check:i18n` (aturan G-01) dan `check:a11y`:

1. **Template literal ber-prosa DILARANG di prop teks.**
   `description={`${bankName} akan dihapus dari daftar.`}` → pengguna English
   membaca bahasa Indonesia, dan kamus hanya menyimpan potongan literalnya.
   Pola benar: `translate("{x} {y} akan dihapus dari daftar.", { x, y })` —
   literalnya terkatalog, nilai runtime diisi lewat slot bernama.
2. **Label gabungan** memakai potongan yang sudah diterjemahkan + `summarize()`
   dari `lib/a11y`:
   `accessibilityLabel={summarize([translate(t.heading), amount])}`.
   Rangkaian manual `.filter(Boolean).join(", ")` diperingatkan gate (audit #4).
3. **Peta label di scope modul** kadang tidak bisa memanggil `translate()` saat
   dimuat — bahasa akan membeku di bahasa saat berkas pertama di-import. Untuk
   kasus itu: bangun label di dalam komponen (fungsi `defaultLabels()`), ATAU
   beri komentar penanda `i18n-shape-aman: <alasan>` bila bagian yang berbeda
   HANYA angka — `maskNumbers` menormalkan angka menjadi token `{x}`, sehingga
   kunci kamusnya identik dengan bentuk runtime.

`check:i18n` juga menolak literal `translate()` yang memuat TOKEN bernama
sekaligus ANGKA (`"{x} memberi {y} dari 5 bintang"`), karena angka itu akan
dimask menjadi token lain dan bertabrakan dengan var — pindahkan angkanya ke
slot (`{ z: 5 }`).

## Kewajiban `useLanguage()` pada pemakai formatter

`lib/format.ts` memilih nama bulan/hari dan label zona saat **dipanggil**
(`getLanguage()`), bukan saat modul dimuat. Konsekuensinya: komponen yang
menampilkan hasil formatter WAJIB memanggil `useLanguage()` (atau merender lewat
`<Text>`, yang sudah berlangganan store) supaya ikut render ulang saat pengguna
menukar bahasa. `components/ui/calendar.tsx` adalah contoh yang diperbaiki pada
audit G-07 — sebelumnya ia punya tabel `MONTHS_ID_LONG`/`WEEKDAYS_ID` sendiri,
jadi pengguna English melihat "Mei 2026" dan pembaca layarnya mendengar
"12 Mei 2026". Sejak itu nama bulan/hari diambil dari `monthName()`/`dayName()`.

## Bentuk string dinamis (`{x}`)

`Saldo Rp1.250.000 keluar` tidak akan pernah sama persis dengan kunci kamus apa
pun. Karena itu `lib/i18n/shape.ts` memaski angka menjadi token `{x}` dan
mencari kamus dalam BENTUK itu, lalu menyisipkan kembali nilainya:

```
kunci   : "Saldo {x} keluar"
English : "Balance {x} out"
input   : "Saldo Rp1.250.000 keluar"  →  output: "Balance Rp1.250.000 out"
```

Yang tidak numeric dan tidak bisa dideteksi dari string jadi (nama orang, slug)
harus ditulis eksplisit di layarnya: `t("Kirim ke {name}", { name })`.

## Urutan bahasa aktif

1. **Preferensi akun** — `GET /v1/settings/language`, ditarik sekali per sesi
   oleh `components/i18n-provider.tsx` dan menang atas semuanya.
2. **Cache perangkat** — `SecureKeys.languagePreference` (expo-secure-store;
   ikut localStorage di web seperti preferensi tema), dipakai sebelum & saat
   offline.
3. **Bahasa OS** — `expo-localization`: `id` hanya bila OS memang Indonesia,
   selain itu `en` (English satu-satunya kamus yang ada).

Ganti bahasa di `/language`: optimistis → store + cache → `PUT`; bila PUT gagal,
bahasa dikembalikan dan toast menampilkan alasan dari server.

## Merawat katalog

```
npm run gen:i18n     # tulis ulang lib/i18n/catalog.json dari sumber
npm run check:i18n   # CI: katalog sinkron + kamus valid + cakupan tidak turun
```

`check:i18n` (→ `scripts/check-i18n.mjs`) menolak:

- kunci di kamus yang tidak ada di katalog (copy Indonesia berubah di kode);
- jumlah token `{x}` berbeda antara kunci & nilai;
- kunci ganda antar file kamus;
- cakupan yang turun dari `lib/i18n/coverage.json` (ratchet).

Kamus dipecah per area (`lib/i18n/en/{labels,auth,tabs,ui,screens-*}.json`)
supaya satu layar bisa diterjemahkan tuntas dalam satu review; daftar kerja per
area: `npm run gen:i18n -- --areas`.

## Known gap (disengaja, tercatat)

- Teks hasil perantaian di layar (`"Rp" + x`) ikut terbaca lewat bentuk `{x}`;
  kalau bentuknya tabrakan, penulis layar menuliskan `t(...)` eksplisit.
- Dokumen hukum & artikel bantuan isinya datang dari backend — tidak ikut
  kamus client. Begitu pula `message` error bawaan backend (selain default
  client di `lib/api/errors.ts`, yang seluruhnya sudah punya padanan EN).
- Template literal di dalam `<Text>` (`{`Durasi ${x}`}`) tidak bisa
  diterjemahkan oleh `localizeChildren` dan **ditolak `check:i18n`** (aturan
  E-03): gunakan pola slot `translate("Durasi {x}", { x })` — literalnya
  terkatalog otomatis oleh `gen-i18n`. Sejak audit G-01 aturan yang sama juga
  berlaku untuk prop teks apa pun (lihat bagian di atas).
- Label zona Waktu Indonesia Barat memakai **`WIB`** di bahasa Indonesia dan
  **`UTC+7`** di English (G-08): pembaca English tidak mengenal singkatan zona
  Indonesia, dan offsetnya bermakna sama tanpa asumsi budaya.

## Roadmap bahasa ketiga (E-09)

Arsitektur siap menambah bahasa tanpa perubahan kode runtime:

1. Tambah kode di `LanguageCode` + entri `LANGUAGES` (`lib/i18n/languages.ts`)
   — sinkronkan dengan enum backend `UpdateLanguageDto.language` TERLEBIH
   DAHULU (backend menolak kode di luar `"id" | "en"`).
2. Buat direktori kamus `lib/i18n/<kode>/` dengan pemecahan file yang sama
   seperti `en/`; `translate.ts` memuat kamus per bahasa secara lazy.
3. `toLanguageCode()` sudah menormalkan varian region (`zh-*`, `ar-*`) —
   tambahkan cabangnya di sana.
4. Kandidat pasar: `zh` & `ar` (segmen TKI/ekspat), `jv`/`su` (penutur Jawa &
   Sunda — saat ini OS berbahasa daerah jatuh ke ID/EN).
5. Untuk `ar`: perlu audit RTL (layout `flex-row`, ikon panah) — NativeWind
   sudah mendukung `rtl:` variant; ini kerja terbesar, bukan kamusnya.
6. `check:i18n` saat ini meratchet cakupan EN saja — generalisasi argumen
   `--lang` sebelum bahasa ketiga dikirim.
